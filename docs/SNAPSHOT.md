# Snapshot contract (v1)

The state owner builds one immutable snapshot per second. Agent tools and the dashboard tab read the same snapshot by its `snapshot_id`, so chat and screen can't disagree. A process that doesn't own the collector asks the owner over `owner.sock` (see `hl_desk/owner.py`). The tab computes nothing; it only formats what the snapshot says. Every metric is defined in `schema/metrics.v1.json`.

## Routes (mounted at `/api/plugins/hyperliquid-desk/`)

A collector that isn't running: `{ok: false, state: "error", market, reason}`; an unknown market or interval: the tool error form `{ok: false, error}`. Directions are only up, down and flat; nothing is a label, a forecast or a signal. |

## Value convention

A metric is `{"value": <number|string>, "unit": "USD"}` or, when unavailable, `{"value": null, "unit": "USD", "reason": "…"}`. Show the reason; never show 0 for null.

Since 1.3.0 the context values (`context.*`) are the one exception: activeAssetCtx carries no source timestamp, so instead of being withheld they are served marked unverified, `{"value": 74990.0, "unit": "USD", "status": "unverified", "reason": "activeAssetCtx carries no source timestamp; a changed value was received 0.4 s ago", "received_age_s": 0.4}`. Show the value marked unverified with its receipt age ("unverified, received 0.4 s ago"), not as unavailable. They are `{"value": null, "unit": …, "reason": …}` as before when the collector is stopped, disconnected or warming up, or when no changed context arrived within the max age (`freshness.ctx.max_age_s`: 20 s for BTC and HYPE, 45 s for the xyz markets), so a dead stream never shows old numbers.

### Flow Deck card (`deck.card`)

When the 90 s window is complete: `{market, window_s, tick_s, tick, window_start_ms, window_end_ms, regime: {value: the confirmed regime} or null+reason, confirmed_regime: {state, tag, since, held_s, as_of_tick, meaning} | null, live_classification: {state, tag, tick, describes, sparse, sparse_note, meaning}, pending: {state, ticks, of} | null, numbers: {price, move_bps, net_flow_usd, volume_usd, impact (descriptive ratio), pressure (aggressive buy / sell notional), top_wallet: {value: address, share_pct, share_label, net_aggressive_usd, aggressive_bought_usd, aggressive_sold_usd, net_label} | null+reason, accounts, trades}, activity_buckets: {new_long, cover, new_short, exit, *_pct, stream: "node fills", provenance, freshness, coverage, ...} from node fills over the card's window when a node feed is configured, else each null with "needs node mode", hook, path: {points: [6 × {tick, tick_ms, price, move_bps, net_flow_usd, volume_usd, trades, reason?}], point_s: 15, first_trade: {time, time_ms, price} | null+reason, note}, dominated_by: {any, threshold_pct: 50, rule, net_flow: {basis_usd | null+reason, tick, print, wallet}, volume: {basis_usd, tick, print, wallet}, summary}}`. The confirmed regime, the live classification and the pending change are separate; the confirmed label never describes the current numbers by itself. `meaning: {state, key_number, text, wording}` comes from schema `regimes.meanings`; each of the three carries `validation`, the same static string for every regime label (schema `regimes.validation`). `path` (schema `deck.path`) is the window as six 15 s points ending at each tick: the points add up to the window's net flow and volume and chain from its first trade to its last; a point with no trades has `price` and `move_bps` null with `reason`. `dominated_by` (schema `deck.dominated_by`) names, for the net aggressive flow and for the volume, the largest tick, print and taker address with `share_pct` and `dominates` (more than 50%), `any` and a quotable `summary`; net shares need |net| ≥ $100K, else `net_flow.basis_usd` is null with the reason.

When it isn't: `regime` and every number are null with the reason (e.g. "window incomplete: needs 90 s after the segment start …"), and `last_confirmed` may hold the last confirmed regime, labeled historical; `path` and `dominated_by` are absent (the card's reason covers them), like `tick` and `window_start_ms`.

## Node mode (`market.node`)

`market.node = {panels, live, replay, separation}`. `live` is the configured node feed's view, or `{available: false, reason}`
(no feed configured, or the feed turned out to serve a REPLAY); `replay` is an explicitly started replay's view, or null. Live
and replay are separate partitions and are never mixed. A view is:

| Key | Shape |
| --- | --- |
| `provenance` | `{source, mode: LIVE/REPLAY, epoch, session, replay_session, stream, market, protocol}` |
| `delay` | the node feed's delay for this market (the tab's counter): `{available, state, reason, delay_ms, current_ms, covered_ms, window_ms, delayed_after_ms, stale_after_ms}`. `delay_ms` is the age of the market's latest watermark (receipt wall time minus block time, plus the time since receipt) averaged exactly over the last `window_ms` (5 s, or since the first watermark); `current_ms` is its value now. A replay has none |
| `families` | per family `book`, `triggers`, `depth`, `bands`, `flow` and, once the handshake named the market's position stream, `owner_pos` (the signed positions behind the stop map's estimate; INVALID with the reason when the feed carries none): `{state: LIVE/BEHIND/STALE/UNKNOWN/INVALID/REPLAY, reason, watermark_block, watermark_block_time_ms, applied_through, watermark_age_ms, source_age_ms, delay_ms, delay_window_ms, delayed_after_ms, stale_after_ms}`. Since Nov 8 a valid family's state comes from `delay_ms`, the market's averaged delay: LIVE up to `delayed_after_ms` (10 s), BEHIND (shown as DELAYED) above it, STALE above `stale_after_ms` (30 s). `watermark_age_ms` (since the latest watermark's receipt) and `source_age_ms` (its age now) are kept for answers. The limits are the ones the state was judged by: a reader holding the status keeps aging it (the tab's gate adds the time since it asked to `delay_ms`; it never blanks the page for a delay, it says so in place). UNKNOWN means the worst clock offset among the session's accepted lines over the last 10 s puts this machine's clock behind the producer's. A watermark without a source time (`block_time_ms` null) advances no family's freshness. A tool reading the latest snapshot re-judges every node status that was LIVE at build time at the moment it serves it (`aged_by_ms`): its `delay_ms` plus the snapshot's age when served (an upper bound) past a limit reads BEHIND or STALE, and every node number built on it (ladder, walls, thinning, stops, tape, the order flow map, Flow Deck and burst node buckets, wallet splits) is withheld with the reason. A snapshot read by `snapshot_id` is historical and stays as of its build time |
| `connection`, `replay` | the source's connection state (with a relay's refusal reason), and a replay's status (state, speed, position, recording span, partial history) |
| `book` | `{valid, reason, crossed: null or {since_seq, best_bid, best_ask}, book_time_ms}`: panels built on the book are `{available: false, reason}` unless valid. Valid means the family is neither INVALID (including crossed) nor UNKNOWN; a BEHIND or STALE book is valid and its panels are served with the state, each carrying `freshness` and an `as_of_note` ("as of the node's book at <block time>, 73.4 s behind"; null while current) |
| `ladder` | `bids`/`asks` rows `{px, total_sz, orders, notional_usd, largest_order_sz, largest_order_time_ms, oldest_order_time_ms, change_10s: {added, absorbed, pulled, unknown}, stops_to_next_level}`, `labels`, `book_time_ms`, best bid/ask, mid. `stops_to_next_level` is `{orders, sz, unknown_size_orders}`; `null` on the last row (no next level); `{available: false, reason}` on every row while the trigger family isn't LIVE (or REPLAY), with `stops_available`/`stops_reason` on the ladder, never 0 |
| `stops` | conditional interest: `rows` `{lo, hi, kind, side, orders, sized_orders, sz, unknown_size_orders, largest_order, dominated, size_check}`, `estimate` {available, reason, as_of_ms, as_of_note, basis, positions_block, triggers_block, same_block, positions_confirmed, triggers_confirmed, confirm_note, owners, whole_position_orders, estimated, counted_at_nearer, upper_bound, unknown, defects, rule} (the whole-position size estimate from the owner position stream; each family's block is the data the estimate uses: the later of its last applied snapshot or delta and its last consistent watermark, `*_confirmed` false and `confirm_note` set while an applied change is ahead of its watermark; `as_of_ms` the older of the two families' block times; freshness stays the watermarks'; each map band adds `estimate` and `total_est_usd`, its walk `ratio_pct_est`; `clusters_by_estimate` one sentence per side when the estimate's largest band differs), `outside` (below, above, no reference price), `accounted`, `excluded_by_engine`, `venue_check`. Since 1.3.0 also the stop map (the stop and liquidity map report; schema `node.stop_walk_ratio`, `node.stop_clusters`, `node.stop_exclusions`): `map` `{available, label, as_of: {book_time_ms, block, note}, ref_px (the book mid), band_pct: 0.5, out_to_pct: 10, sides: {fall: {side: "sell", label: "Sell-side triggers", book_side: "bids_below", fires_on, members, depth_total_usd, bands: [20 x {side, fires_on, book_side, k, band: {lo, hi, near_px, far_px, from_pct, to_pct}, distance_pct, orders, sized_orders, unknown_size_orders, accounts, sz, notional_usd, lower_bound (true when some of the orders have no size: the notional is at least this), unknown_size_orders (beside it; null notional + notional_reason "every order is whole-position: size unknown, not 0" when every order is unsized; notional_note when some are), by_category: {sell_stop_on_fall \| buy_take_profit_on_fall \| buy_stop_on_rise \| sell_take_profit_on_rise: {orders, sized_orders, unknown_size_orders, accounts, notional_usd}}, largest_order, walk: {ratio_pct (null + ratio_reason), lower_bound, unknown_size_orders, depth_at_and_beyond_usd, depth_between_usd, depth_bands_used: {side, k_from, k_to, includes_band: true, from_pct, to_pct, note}, depth_source}}]}, rise: {side: "buy", label: "Buy-side triggers", book_side: "asks_above", ...}}, rules, venue_check}` or `{available: false, reason}` without a valid book; `clusters` the two bands per side with the largest stated notional, each a band row plus `rank` and `text` (the report's sentence: "Sell-side triggers at <near_px> to <far_px> (-1.0% to -1.5%): at least $109K across 83 orders from 79 accounts; the bids at and below it total $24.47M, so this cluster is at least 0.44% of the liquidity it would walk; 33 of 83 orders report no size, so this is understated", "at least" and the last clause only when some orders have no size), or `null` with `clusters_reason`; `exclusions` `{available, note, order, trailing_stops: {orders (the engine's count), notional_usd: null, reason}, unclassified_by_engine, implausible_price, already_true_at_price, beyond_range, size_outlier: each {orders, sized_orders, unknown_size_orders, accounts, notional_usd, by_category, rule}, accounted: {waiting_triggers, in_bands, excluded_here, complete}}` or `{available: false, reason}` (each waiting trigger once, under the first rule that applies in `order`: a trigger price outside [mid / 10, mid x 10] or not positive; a fall trigger at or above the mid or a rise trigger at or below it; more than 10% away; and last, inside the bands only, a size outlier: an order whose stated size, at its trigger price, is worth more than everything resting at and beyond its band out to 10% on the side it fires into, the band's `walk.depth_at_and_beyond_usd`, so it could not be walked through the book; orders with no stated size never qualify; `size_outlier.rule` says so in a sentence, and the `orders` and `notional_usd` beside it are what the rule left out); `census` (the reviewer's sanity checks; schema `node.stop_census`) `{triggers_total, triggers_through_seq, unsized_total, excluded_by_engine (the applied waiting set now), within_10pct, outside, unsized_within_10pct (read from the engine's own bands view, summed, never recounted, with `bands_view: {ref_px, range_bps, width, lo, hi, block, block_time_ms, seq, by_category, outside: {below, above}, excluded_by_engine, source}`), excluded (the map's, by reason, with excluded_by_engine), executable_orders_total (the client's book now), executable_within_10pct: {orders, ref_px, ref_px_source, range_bps, book_time_ms, source} (the book's resting orders inside the bands view's range), executable_to_trigger_ratio (now), snapshot_totals: {book: {total_orders, block, block_time_ms}, triggers: {total_triggers, block, block_time_ms}, executable_to_trigger_ratio, note} or null + snapshot_totals_reason "no snapshot totals yet"}`; a count whose source isn't valid is null with `<name>_reason`, never 0. A map band's edges are the thinning panel's (`k = floor(distance / 0.5%)`), so its `walk` sums that panel's bands: `depth_at_and_beyond_usd` is the band and every band farther from the price on the walked side (the report's "bids at and below it"), `depth_between_usd` the bands nearer than it; `ratio_pct = notional_usd / depth_at_and_beyond_usd x 100`. The whole-position rule is the rows': a lower bound where such orders sit (understated), unknown, never 0, when every order is one. When the book lapses by serving time, `map` is `{available: false, reason}`, `clusters` null with `clusters_reason` and the census's book-built counts (`excluded`, `executable_orders_total`, `executable_within_10pct`, `executable_to_trigger_ratio`) null with reasons; when the bands family lapses, the census's `within_10pct`, `outside`, `unsized_within_10pct` and `bands_view` are null with reasons; when the triggers lapse, the whole `stops` is withheld |
| `walls`, `history`, `thinning`, `tape` | wall watch; the 15-minute heatmap samples (partial until covered); the liquidity-thinning bands with the sharpest drop and its note (since 1.3.0 each band also carries `cumulative_from_price_usd`, the resting notional from the current price out to and including that band on its side); the node tape with flags and its coverage |
| `flow_map` | the Order Flow Map (the order-flow map report in node mode; schema `node.flow_map`): aggressive (taker) flow over eight 15-minute buckets aligned to the clock, each node fill once, the taker side only, split by the taker's own position effect into risk opened (Open Long, Open Short), closed (Close Long, Close Short) and flipped (Short > Long, Long > Short). `{available: true, window: {start_ms, end_ms, bucket_s: 900, buckets: 8, coverage_s, complete, uncovered: [{start_ms, end_ms, why}], note}, buckets: [8 × {start_ms, end_ms, buy_usd, sell_usd, net_usd, open_long_usd, close_short_usd, open_short_usd, close_long_usd, flip_usd, flip_to_long_usd, flip_to_short_usd, risk_added_usd, risk_removed_usd, fills, flip_fills, unclassified_usd, unclassified_fills, unreadable_fills, accounts, top_account_share_pct, coverage_s, complete, in_progress, reason}], totals: {the same sums over the eight buckets, plus aggressive_usd = buy_usd + sell_usd}, accounts: {top: {address, notional_usd, share_pct} or null, top5_share_pct, distinct, unattributed_usd, basis_usd, basis}, readings: [{kind: net, composition, risk, concentration (or the one kind empty; plus unclassified when any fill couldn't be classified or read), text, basis}], counting, units_note, counters, stream: "node fills", provenance, freshness}`. `buy_usd = open_long + close_short + flip_to_long`, `sell_usd = close_long + open_short + flip_to_short`, `risk_added = open_long + open_short`, `risk_removed = close_long + close_short`, flips apart, so `buy + sell = risk_added + risk_removed + flip`. The last bucket is in progress (`end_ms` is the latest block time whose fills are known); a bucket that starts before the node fills were observed or spans a gap has `complete: false` with its `coverage_s` and `reason`, never scaled or filled in. Columns: up = taker buying, down = taker selling; the readings are quoted verbatim, never recomputed. `{available: false, reason: "node fills <state>: …", stream, provenance, freshness}` while the flow family isn't LIVE or REPLAY, and (with `window` kept) when it has lapsed by the time a latest snapshot is served |
| `liquidation_events` | liquidation bursts (also merged into `deck.events`) |

Each market's view also has `bursts` (the node burst rule's status, as in `deck.bursts`). Flow Deck cards carry `activity_buckets` from node fills (`stream: "node fills"`), node burst events `node_activity` (their side only, from exactly the burst's executions), and
wallet panels `node_activity_split`; each is unavailable with a reason when the node fills don't cover its window, except when the only gap is that the node hasn't processed through the window's end: the card's buckets and the wallet split then cover the last window of the same length the fills do cover, with `window` (the covered bounds, `requested`, `shifted_by_ms`), `window_label` and `as_of_note`; a burst's own window is never shifted. Top level:
`node_status` (live connection, configured settings, replay status). With a relay (the hosted default included),
`node_status.live.relay` = `{hosted_default, views: {<market>: "full" | "execs"}, relay_heartbeat: {state, publisher,
message, recv_wall_ms} or null (the relay's own heartbeat: never a freshness source), demand: {panel_on_screen,
open_market, seconds_since_panel, unsubscribes_in_s, linger_s: 60, alerts_in_background, subscription: {full,
execs} or null}, tool_subscriptions: {<market>: {connection, leases}}}`, and `live.connection.state` can also be
`idle` (node data paused: no node panel on screen for 60 s), `full` (the relay is at capacity), `stopped` (switched
off by its operator) or `refused` (another refusal: per-address limit, reconnect rate, a redirect), each with the
plain `reason` the node panels show.
